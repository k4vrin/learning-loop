# Source policy

Use this policy whenever a track depends on researched or unstable material.

- Prefer official documentation, specifications, standards, original papers,
  maintainers, and first-party curricula.
- Record the source title, owner, direct URL or workspace note, purpose, and the date
  it was verified.
- Separate source-supported requirements from pedagogical choices and inference.
- For evolving technologies, verify version-sensitive behavior during the
  current run.
- Paraphrase reference answers and link to sources. Do not reproduce chapters,
  paid courses, proprietary question banks, or answer keys.
- If browsing is unavailable, preserve the gap as an explicit search task.
- Add material only when it helps the target performance; release-note novelty
  alone is not sufficient.
