# Review Learning Progress

Judge demonstrated performance, not activity volume.

Resolve `<plugin-root>` as the nearest ancestor of this `SKILL.md` that contains
the portable root `plugin.json`. Do not assume the process working directory.

## Workflow

1. Resolve and validate the learning folder.
2. Read active track goals, readiness gates, recent append-only session attempts,
   due-card state, and retained assessment evidence.
3. Apply [references/progress-review.md](references/progress-review.md).
4. Separate findings into:
   - retained strengths;
   - repeated gaps;
   - confidence-calibration problems;
   - untested capabilities;
   - source or rubric uncertainty.
5. Run a representative mixed or transfer assessment when evidence is insufficient.
6. Adapt future work narrowly:
   - keep due recall ahead of new material;
   - add repair prompts for repeated gaps;
   - retire duplicates;
   - reduce new-card volume when adherence or recall is weak;
   - advance only after the track's stated threshold is demonstrated.
7. Record the review in `Assessments/` or the track note with date, evidence,
   decision, and next checkpoint.

## Boundaries

- Do not rewrite historical session attempts.
- Do not infer mastery from time spent, streaks, completion, or agent praise.
- Do not penalize missed days by multiplying the next session.
- Do not change the learner's target outcome silently when reducing scope.
